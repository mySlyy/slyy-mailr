Simple Mail & Calendar Client (Outlook Replacement)

Spec dated 26 Nov 2026. This is the first spec, written before the native Swift build: where the app now differs (native macOS/iOS instead of a web app, no backend, mailcow with SOGo), the backlog and the code are what's current.

Overview

Build a lean web + desktop client (working name Mailr) that replaces Outlook for internal staff: mail over our own IMAP/SMTP, a CalDAV calendar with meeting invites, and one-click Jitsi video calls on vid.rocket.re-cloud.io. Scope is deliberately smaller than Outlook: the 20% of features used 95% of the time.

Goals

  • Read, write, search, file mail on our IMAP/SMTP server; multiple accounts per user.
  • Calendar: day/week/month views, create events, send/receive invites (iCalendar/iTIP), shared team calendars.
  • Every meeting can carry a video link; join from mail, calendar or reminder in one click.
  • Runs in the browser (PWA) and as a desktop app; German and English UI.

Non-goals (v1)

  • Exchange/EWS, MAPI, Microsoft 365 connectivity.
  • PST import (use IMAP migration on server side instead), tasks/to-dos, notes, RSS.
  • S/MIME, PGP, mail rules engine beyond server-side Sieve.
  • Native mobile apps (PWA on mobile is acceptable).

Users: ~5–50 internal staff, office + remote. Primary devices: Windows/macOS laptops, secondary: phones.

Architecture

Browsers cannot speak IMAP/SMTP, so a thin Mailr backend sits between the clients and our mail and CalDAV servers. Video media flows directly between client and Jitsi.

Stack (proposal): TypeScript throughout. Frontend React PWA; desktop = same build in a Tauri shell. Backend Node.js with ImapFlow (IMAP), Nodemailer (SMTP), tsdav (CalDAV/CardDAV), ical.js (iCalendar), PostgreSQL for sync state + search index. Deployed as Docker containers next to the mail server. The backend stores no mail permanently beyond the cache; IMAP stays the source of truth.

Mail (IMAP / SMTP)

The client talks only to our own servers. IMAP for reading and folders, SMTP submission for sending, server-side Sieve for rules and out-of-office.

Protocols

  • IMAP4rev1 over TLS (993), extensions used when offered: IDLE (push), CONDSTORE/QRESYNC (fast sync), MOVE, UIDPLUS, SPECIAL-USE (Sent/Drafts/Trash/Junk/Archive detection), SORT/THREAD, QUOTA.
  • SMTP submission on 587 (STARTTLS) or 465 (TLS), AUTH PLAIN/LOGIN; XOAUTH2 optional later.
  • ManageSieve (4190) for filters and vacation reply.
  • Autoconfig: read autoconfig.<domain>/mail/config-v1.1.xml; user only types email + password.

Calendar

Calendar data lives on a CalDAV server, not in the client. Invites travel as standard iCalendar (RFC 5545) over iTIP/iMIP (RFC 5546/6047), so external Outlook, Google and Apple users can accept them.

Server: IMAP/SMTP do not store calendars. We need a CalDAV/CardDAV server next to the mail server: Radicale (minimal) or SOGo / Nextcloud (with shared calendars + free/busy). Auth against the same user directory as IMAP. See open questions.

Features (v1)

  • Views: day, work week, week, month, agenda list; side-by-side overlay of several calendars with colours.
  • Create/edit events: title, time, all-day, time zone, location, description, recurrence (daily/weekly/monthly/yearly, end by date/count, exceptions), reminders (popup + email).
  • Invites: add attendees, client sends METHOD:REQUEST via SMTP; replies (REPLY) update attendee status; cancel sends CANCEL. Prefer server-side scheduling (CalDAV Scheduling, RFC 6638) when the server supports it.
  • Incoming invites in the inbox: Accept / Tentative / Decline / Propose new time; accepted event written to default calendar.
  • Free/busy lookup for internal attendees when creating a meeting (scheduling assistant: one row per attendee, busy blocks shown).
  • Shared calendars: team and room calendars, read-only or read-write per user.
  • Subscribe to external ICS feeds (holidays, public calendars), read-only.
  • Drag to move/resize events; quick-create by click in an empty slot.
  • Reminder notifications on desktop/browser; "Join" button inside the reminder when the event has a video link.
  • Import/export .ics files (for one-off migration from Outlook).

Video calls (vid.rocket.re-cloud.io)

vid.rocket.re-cloud.io runs Jitsi Meet (docker-jitsi-meet; checked 2026-11-26). Its public config shows no authentication domain, so anyone with a room URL can join. The client generates the room, puts the link into the event, and embeds the call.

Integration

  • Room URL: https://vid.rocket.re-cloud.io/<room>; room name = random, unguessable slug (≥ 16 chars, e.g. mailr-7f3k9q2xw4bt8zne), never the meeting title.
  • "Add video call" toggle in the event form (default on for events with attendees). Writes the link to: iCalendar LOCATION (if empty), URL, X-JITSI-URL, and a "Join video call" block at the top of DESCRIPTION, so Outlook/Google/Apple recipients see it too.
  • Optional dial-in/PIN block if the server later offers phone dial-in.
  • Join points: event popover, invite card in mail, reminder notification, "Meet now" button in the toolbar (ad-hoc room + copy link), "Call" action on a contact or mail thread (creates room, sends link).
  • Embedded call: Jitsi IFrame API (https://vid.rocket.re-cloud.io/external_api.js) in an in-app window; display name and email pre-filled from the account; option "open in browser" instead.
  • Desktop app: grant camera/mic/screen-share permissions to the Jitsi origin only.

Security

  • Short term: unguessable names + Jitsi lobby enabled by the organiser (moderator) for external meetings.
  • Recommended: enable JWT auth on the Jitsi server (ENABLE_AUTH=1, AUTH_TYPE=jwt). The Mailr backend then signs short-lived tokens for internal users (moderator rights); guests join through the lobby. Spec the token claims once the server change is agreed.
  • Optional: end-to-end encryption toggle for small internal calls.

Contacts, security, non-functional

Contacts: CardDAV address book on the same server as the calendar; personal + shared company address book. Auto-collect recipients into a "Collected" book. Optional read-only sync of Odoo res.partner into the shared book (one-way, nightly).

Security

  • TLS everywhere; reject plain IMAP/SMTP. Certificate pinning not required.
  • Credentials: stored in OS keychain (desktop) or encrypted server-side session (web); never in localStorage.
  • 2FA: web login supports TOTP; IMAP/SMTP use per-device app passwords if the server supports them.
  • HTML mail rendered in a sandboxed iframe with strict CSP; attachments never auto-opened.
  • GDPR: data stays on our servers (mail, CalDAV, Jitsi, backend all self-hosted, EU); no third-party telemetry; logs keep no message content, 30-day retention.

Milestones, acceptance, open questions

Four phases, ~14 weeks for 2 developers (estimate; confirm after open questions).

  1. M1 Mail core (wk 1–5): account setup via autoconfig, sync, read, compose, send, folders, search, offline cache. Pilot with 3 users.
  2. M2 Calendar (wk 6–9): CalDAV server live, views, events, recurrence, iTIP invites, invite cards in mail, .ics import.
  3. M3 Video + contacts (wk 10–11): Jitsi links in events, Meet now, embedded call, reminders with Join; CardDAV contacts, autocomplete.
  4. M4 Rollout (wk 12–14): desktop builds, Sieve/out-of-office, shared calendars, free/busy; migrate all users, Outlook switched off.

Acceptance criteria

  • New user is set up with email + password only, in < 2 min.
  • Mail sent from Mailr arrives with correct headers at Gmail and Outlook.com (not spam).
  • Invite sent from Mailr is accepted in Outlook and Google Calendar; the reply updates the attendee status in Mailr.
  • Invite from Outlook is shown as invite card in Mailr; Accept puts it in the calendar.
  • Every meeting with attendees carries a working vid.rocket.re-cloud.io link that external recipients see in their own client.
  • "Join" from reminder opens the call with camera/mic in ≤ 2 clicks.
  • Pilot users run 2 weeks without Outlook.

Open questions

  • Which IMAP/SMTP server do we run (Dovecot/Postfix, Mailcow, Stalwart, other)? Does it ship CalDAV/CardDAV (e.g. SOGo in Mailcow, Stalwart's built-in)?
  • Where do existing Outlook calendars live (Exchange, local PST)? Defines the migration path.
  • Will the Jitsi server get JWT auth, and who administers it?
  • Build vs. adopt: SOGo, Roundcube + plugins or Thunderbird cover most of this spec today. Is a custom client required (branding, Odoo integration), or would configuring one of these be enough?
  • Web-only first, or desktop app needed from day one?
